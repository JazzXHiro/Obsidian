# textContent vs innerHTML

---

# 🧠 What They Are (Short Definitions)

### `textContent`

> Sets or gets **plain text only** inside an element.

### `innerHTML`

> Sets or gets **HTML markup** inside an element.

---

## 🔍 `textContent` — Plain Text Only (Safe)

```js
element.textContent = "Hello <b>World</b>";
```

### Result in browser:

```
Hello <b>World</b>
```

✔ Tags are treated as text  
✔ No HTML parsing  
✔ No execution  
✔ Very safe

---

### When to use `textContent`

- Showing messages
    
- User input
    
- Status text
    
- Notifications
    
- Any dynamic content from JS
    

**This should be your default choice.**

---

## 🔍 `innerHTML` — Parses HTML (Powerful but Dangerous)

```js
element.innerHTML = "Hello <b>World</b>";
```

### Result in browser:

```
Hello World
```

(with **World bolded**)

✔ HTML is parsed  
✔ DOM nodes are created  
❌ Can execute scripts

---

## 🚨 Security Risk (Very Important)

```js
element.innerHTML = userInput;
```

If `userInput` is:

```html
<script>alert("Hacked!")</script>
```

➡️ **XSS attack** (Cross-Site Scripting)

This is why `innerHTML` is dangerous if misused.

---

## 🆚 Side-by-Side Comparison

|Feature|`textContent`|`innerHTML`|
|---|---|---|
|Interprets HTML|❌ No|✅ Yes|
|Executes scripts|❌ No|❌/⚠️ Yes|
|Security|⭐⭐⭐ Safe|⚠️ Risky|
|Performance|Faster|Slower|
|Use case|Text updates|HTML templates|

---

## 🧠 Performance Difference

- `textContent`
    
    - Just replaces text
        
    - No parsing
        
    - Faster
        
- `innerHTML`
    
    - Parses HTML
        
    - Builds DOM nodes
        
    - Triggers reflow/repaint
        

For small updates → always use `textContent`.

---

## 🎯 Interview-Ready Explanation

> “`textContent` inserts plain text and prevents HTML execution, while `innerHTML` parses and renders HTML, which can introduce security risks.”
