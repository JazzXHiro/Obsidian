# Padding-Inline

Great — **`padding-inline`** is part of **modern, logical CSS**, and it pairs perfectly with `padding-block`.

---

## 🧠 What is `padding-inline`?

> **`padding-inline` sets padding in the _inline (text) direction_ of the document.**

In most languages (English, left-to-right):

- **inline-start** → left
    
- **inline-end** → right
    

So:

```css
padding-inline: 2rem;
```

means:

```css
padding-left: 2rem;
padding-right: 2rem;
```

---

## 🔍 Why It’s Called _Inline_

CSS has two logical directions:

|Direction|Meaning|
|---|---|
|**Block**|Vertical flow (top → bottom)|
|**Inline**|Text flow (left → right or right → left)|

`padding-inline` works **along the text flow**, not physical sides.

---

## 🧩 Syntax Variations

### 1️⃣ One value

```css
padding-inline: 2rem;
```

Applies:

- `inline-start = 2rem`
    
- `inline-end = 2rem`
    

---

### 2️⃣ Two values

```css
padding-inline: 1rem 3rem;
```

Order:

```text
padding-inline: start  end
```

Equivalent to:

```css
padding-left: 1rem;
padding-right: 3rem;
```

_(in LTR languages)_

---

## 🔁 How It Adapts to Languages

This is why `padding-inline` exists.

### Left-to-Right (English)

```css
padding-inline-start → left
padding-inline-end   → right
```

### Right-to-Left (Arabic)

```css
padding-inline-start → right
padding-inline-end   → left
```

Your layout **automatically adapts**.

If you used:

```css
padding-left
padding-right
```

…it would break RTL layouts.

---

## 🧠 `padding-inline` vs `padding-left/right`

|Property|Direction|RTL Safe|
|---|---|---|
|`padding-left/right`|Physical|❌ No|
|`padding-inline`|Logical|✅ Yes|

---

## 🧪 Real Example (Navbar)

```css
.nav {
  padding-block: 1.5rem;
  padding-inline: 2rem;
}
```

Meaning:

- Vertical padding → block direction
    
- Horizontal padding → inline direction
