# resize; none - CSS

`resize: none;` **disables the resize handle** on textarea elements, so users can't manually resize the text area.

### What it does:

**Without `resize: none;`:**
```
┌─────────────────────────┐
│                         │
│   Message textarea      │
│                         │
└─────────────────────────┘ ← Resize handle (draggable corner)
                           ↘
```

Users can drag the corner to make it bigger or smaller, which can break your layout.

**With `resize: none;`:**
```
┌─────────────────────────┐
│                         │
│   Message textarea      │
│                         │
└─────────────────────────┘  ← No resize handle
```

The textarea stays **fixed at 10rem height** (defined by `height: 10rem;` on the same element).

### In your code:

```css
.contact__area {
  height: 10rem;      /* Fixed height of ~160px */
  resize: none;       /* Users can't resize it */
}
```

This ensures your contact form maintains consistent dimensions and doesn't get accidentally resized by visitors, which keeps your design clean and predictable.

---

You're right to question it! The necessity depends on your specific HTML setup.

`resize: none;` is **only needed if your textarea doesn't have other constraints** that prevent resizing.

**Cases where you'd need it:**
- Textarea with `width: 100%` and no max-height constraint
- You want to guarantee users can't resize, regardless of browser behavior

**Cases where it might be redundant:**
- If your textarea is constrained by a flex/grid container with fixed dimensions
- The parent container doesn't allow overflow

Since your `.contact__area` has `height: 10rem;` and is inside a grid container (`.contact__form`), the browser might naturally prevent resizing because the element is already size-constrained.

**However, it's good practice to include it anyway** because:
1. It's explicit and guarantees the behavior across all browsers
2. It prevents unexpected layout shifts if someone removes height constraints later
3. It documents your intent: "this textarea should not resize"

**You could safely remove it** if you test and confirm it works without it in all browsers you support. But keeping it is the safer choice for consistent, predictable behavior.
