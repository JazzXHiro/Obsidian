### Q1. Define CMAC.

**CMAC (Cipher-based Message Authentication Code)** is a block cipher-based message authentication code algorithm. It is used to provide authenticity and integrity assurance for data. CMAC fixes security deficiencies found in the CBC-MAC (Cipher Block Chaining-Message Authentication Code) method. It works by using a symmetric key block cipher (like AES or Triple DES) to create a "tag" for a message. If the message is altered or the sender is not valid, the tag will not match.

### Q2. Explain Diffie-Hellman Key exchange algorithm.

The **Diffie-Hellman Key Exchange** is a method for securely exchanging cryptographic keys over a public channel. It was one of the first public-key protocols.

- **Concept:** It allows two parties (Alice and Bob) to generate a shared secret without ever transmitting the secret itself.
    
- **Process:**
    
    1. Both parties agree on a large prime number $p$ and a generator $g$ (public).
        
    2. Alice picks a private key $a$ and calculates $A = g^a \pmod p$. She sends $A$ to Bob.
        
    3. Bob picks a private key $b$ and calculates $B = g^b \pmod p$. He sends $B$ to Alice.
        
    4. Alice computes $S = B^a \pmod p$.
        
    5. Bob computes $S = A^b \pmod p$.
        
    6. Both now possess the same shared secret $S$ (since $(g^b)^a = (g^a)^b$).
        

### Q3. Elaborate Digital Signature Scheme.

A **Digital Signature Scheme** is a mathematical scheme for verifying the authenticity of digital messages or documents. It is the digital equivalent of a handwritten signature or stamped seal. It relies on **Asymmetric Cryptography**.

- **Key Generation:** Users generate a Public Key and a Private Key.
    
- **Signing:** The sender uses their **Private Key** to sign a message digest (hash).
    
- **Verification:** The receiver uses the sender's **Public Key** to verify the signature. If the math holds, it proves the message came from the sender and has not been altered.
    

### Q4. Describe the terms worms, virus, trojan, and spyware.

- **Virus:** A type of malware that attaches itself to a legitimate program (host). It requires human action (like opening a file) to run and replicate.
    
- **Worm:** A standalone malware program that replicates itself to spread to other computers. unlike a virus, it does not need to attach itself to an existing program or require user intervention to spread.
    
- **Trojan (Trojan Horse):** Malware that disguises itself as legitimate software. Users are tricked into loading and executing it on their systems. It does not replicate but opens a backdoor for attackers.
    
- **Spyware:** Software installed without the user's knowledge to gather information about them (passwords, browsing habits) and send it to another entity.
    

### Q5. Discuss the various services provided by digital signature.

Digital signatures provide three core security services:

1. **Authentication:** It gives the receiver assurance that the message was created by a known sender (since only the sender has the private key).
    
2. **Data Integrity:** It ensures the message was not altered in transit. Any change to the message would result in a different hash, causing verification to fail.
    
3. **Non-Repudiation:** The sender cannot deny having signed the message later, as only their unique private key could have created that specific signature.

### Q6. Describe the key generation process of RSA. Encryption Calculation.

**RSA Key Generation Process:**

1. Select two large distinct prime numbers $p$ and $q$.
    
2. Compute $n = p \times q$. ($n$ is the modulus for both keys).
    
3. Compute Euler's totient function: $\phi(n) = (p-1)(q-1)$.
    
4. Choose an integer $e$ (Public exponent) such that $1 < e < \phi(n)$ and $gcd(e, \phi(n)) = 1$.
    
5. Determine $d$ (Private exponent) such that $d \times e \equiv 1 \pmod{\phi(n)}$.
    

Problem Solution:

Given: Message $M=5$, $p=7$, $q=11$, $e=13$.

1. Calculate n:
    
    $$n = 7 \times 11 = 77$$
    
2. Calculate Ciphertext (Encryption):
    
    The formula for encryption is $C = M^e \pmod n$.
    
    $$C = 5^{13} \pmod{77}$$
    
    Calculation:
    
    $5^1 \equiv 5 \pmod{77}$
    
    $5^2 = 25 \pmod{77}$
    
    $5^4 = 625$. $625 / 77 = 8$ with remainder $9$. So, $5^4 \equiv 9 \pmod{77}$.
    
    $5^8 \equiv 9^2 = 81 \equiv 4 \pmod{77}$.
    
    Combine to get $5^{13}$:
    
    $$5^{13} = 5^8 \times 5^4 \times 5^1$$
    
    $$\equiv 4 \times 9 \times 5 \pmod{77}$$
    
    $$\equiv 36 \times 5 \pmod{77}$$
    
    $$\equiv 180 \pmod{77}$$
    
    $180 / 77 = 2$ remainder $26$ ($77 \times 2 = 154$, $180 - 154 = 26$).
    
    **Encrypted Value (C) = 26**
    

### Q7. Explain Zero Knowledge Protocol.

**Zero-Knowledge Protocol (ZKP)** is a cryptographic method by which one party (the Prover) can prove to another party (the Verifier) that they know a value $x$, without conveying any information apart from the fact that they know the value $x$.

- **Core Analogy:** The "Ali Baba Cave" analogy. A prover can prove they have the magic word to open a door inside a circular cave without revealing the magic word to the verifier standing outside.
    
- **Three Essential Properties:**
    
    1. **Completeness:** If the statement is true, an honest verifier will be convinced by an honest prover.
        
    2. **Soundness:** If the statement is false, no cheating prover can convince the honest verifier that it is true (except with negligible probability).
        
    3. **Zero-Knowledge:** If the statement is true, no verifier learns anything other than the fact that the statement is true.
        

### Q8. Illustrate IPSEC. Define the protocols under IPSEC.

**IPSec (Internet Protocol Security)** is a suite of protocols that secures IP communications by authenticating and encrypting each IP packet of a communication session. It operates at the **Network Layer (Layer 3)**.

**Protocols under IPSec:**

1. **Authentication Header (AH):**
    
    - Provides data integrity and origin authentication.
        
    - It does _not_ provide confidentiality (encryption). It protects against replay attacks.
        
2. **Encapsulating Security Payload (ESP):**
    
    - Provides confidentiality (encryption), data origin authentication, connectionless integrity, and anti-replay service.
        
    - This is the protocol used to encrypt the actual data payload.
        
3. **Internet Key Exchange (IKE):**
    
    - Used to set up a Security Association (SA). It handles the negotiation of protocols and algorithms and generates the encryption and authentication keys to be used.
        

### Q9. Describe PGP algorithm in detail.

_(Or S/MIME - Solving PGP as the primary option)_

**PGP (Pretty Good Privacy)** is a cryptosystem used for secure email communication and file storage. It uses a "Web of Trust" model rather than a strict hierarchical Certificate Authority system.

**Key Operations of PGP:**

1. **Confidentiality:**
    
    - PGP generates a random session key (symmetric) for the message.
        
    - The message is encrypted using the session key (using algorithms like CAST-128 or IDEA).
        
    - The session key itself is encrypted using the receiver's Public Key (RSA).
        
    - The encrypted message and encrypted session key are sent.
        
2. **Authentication (Digital Signature):**
    
    - PGP creates a hash code (SHA) of the message.
        
    - The hash is signed (encrypted) using the sender's Private Key.
        
    - The receiver validates this using the sender's Public Key.
        
3. **Compression:**
    
    - PGP compresses the message (usually using ZIP) after signing but before encryption to save space and increase security (reduces redundancy for cryptanalysis).
        
4. **Radix-64 Conversion:**
    
    - Converts the binary encrypted data into ASCII text (Radix-64) so it can pass through arbitrary email systems without corruption.

### Q10.

Q10 (a) Apply Extended Euclidean Algorithm on GCD (171, 13).

We need to find the Greatest Common Divisor (GCD) and express it as $171x + 13y = \text{gcd}$.

1. Euclidean Algorithm steps:
    
    $$171 = 13 \times 13 + 2$$
    
    $$13 = 2 \times 6 + 1$$
    
    $$2 = 1 \times 2 + 0$$
    
    GCD is 1.
    
2. Extended steps (Back Substitution):
    
    From line 2: $1 = 13 - (2 \times 6)$
    
    From line 1: Substitute $2 = 171 - (13 \times 13)$ into the equation.
    
    $$1 = 13 - [(171 - 13 \times 13) \times 6]$$
    
    $$1 = 13 - [171 \times 6 - 13 \times 78]$$
    
    $$1 = 13 + 13 \times 78 - 171 \times 6$$
    
    $$1 = 13(1 + 78) - 171(6)$$
    
    $$1 = 13(79) - 171(6)$$
    

**Q10 (b) Differentiate between symmetric and asymmetric key cipher.**

| **Feature**      | **Symmetric Key Cipher**                                       | **Asymmetric Key Cipher**                                          |
| ---------------- | -------------------------------------------------------------- | ------------------------------------------------------------------ |
| **Keys**         | Uses a single shared secret key for encryption and decryption. | Uses a pair of keys: Public (encryption) and Private (decryption). |
| **Speed**        | Very fast and efficient (good for bulk data).                  | Computationally heavy and slow.                                    |
| **Key Exchange** | Difficult; key must be shared secretly beforehand.             | Easier; public keys can be distributed openly.                     |
| **Examples**     | DES, AES, RC4, Blowfish.                                       | RSA, ECC, Diffie-Hellman.                                          |

### Q11. Explain SHA-512 algorithm in detail.

_(Solving SHA-512 as the primary option)_

**SHA-512 (Secure Hash Algorithm)** is a cryptographic hash function that produces a 512-bit (64-byte) message digest. It belongs to the SHA-2 family.

**Process Steps:**

1. **Append Padding Bits:** The message is padded so its length is congruent to 896 modulo 1024. Padding consists of a single '1' bit followed by necessary '0' bits.
    
2. **Append Length:** A 128-bit block representing the length of the original message is appended to the end. The total message length is now a multiple of 1024 bits.
    
3. **Initialize Hash Buffer:** SHA-512 uses eight 64-bit registers (A, B, C, D, E, F, G, H). These are initialized with specific constant values (fractional parts of square roots of the first 8 primes).
    
4. **Process Message in 1024-bit Blocks:**
    
    - The message is split into blocks ($N$) of 1024 bits.
        
    - **Message Schedule:** Each block is expanded into 80 words ($W_0$ to $W_{79}$) of 64 bits each.
        
    - **Compression Function:** The algorithm performs 80 rounds of processing for each block.
        
    - In each round, the buffers (A through H) are updated using logical operations:
        
        - **$\text{Ch}(E,F,G)$:** Choice function.
            
        - **$\text{Maj}(A,B,C)$:** Majority function.
            
        - **$\Sigma$ (Sigma):** Rotational operations.
            
        - **$K_t$:** A sequence of 80 constant 64-bit words (derived from cube roots of primes).
            
5. **Output:** After all $N$ blocks are processed, the final values in the buffers A through H are concatenated to produce the **512-bit message digest**.
