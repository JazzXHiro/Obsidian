# Network Models

**Study Notes: Chapter 2 - Network Models**

---

### **2.1 Layered Tasks**  
- **Concept**: Layering simplifies complex communication tasks (e.g., postal mail system).  
  - **Sender**: Creates and sends data.  
  - **Receiver**: Receives and interprets data.  
  - **Carrier**: Transports data (analogous to network infrastructure).  
- **Hierarchy**: Tasks are divided into higher, middle, and lower layers for efficiency.  

---
### **Difference Between Frames and Bits**  

### **Bits**  
- **Definition**: The smallest unit of data in computing, represented as binary digits (0s and 1s).  
- **Layer**: Handled by the **Physical Layer** (Layer 1) of the OSI model.  
- **Role**: Transmitted as raw electrical, optical, or radio signals over a physical medium (e.g., cables, Wi-Fi).  
- **Structure**: No headers, trailers, or formatting—just a stream of binary data.  
- **Example**: A sequence like `01011010` sent over a wire.  

### **Frames**  
- **Definition**: Structured data units that encapsulate bits with control information.  
- **Layer**: Handled by the **Data Link Layer** (Layer 2) of the OSI model.  
- **Role**: Ensure reliable **hop-to-hop delivery** (e.g., between two directly connected devices).  
- **Structure**: Include:  
  - **Header**: Contains addressing (e.g., MAC addresses), error detection (e.g., CRC), and control flags.  
  - **Payload**: The actual data (bits from the physical layer).  
  - **Trailer**: Error-checking information (e.g., Frame Check Sequence).  
- **Example**: An Ethernet frame with MAC addresses, payload data, and a CRC checksum.  

### **Packet**
A **packet** is a structured unit of data used in network communication to route information from a source to a destination across interconnected networks. It operates at the **Network Layer (Layer 3)** of the OSI model and is central to how the internet works. Here's a breakdown:

#### **Key Difference**

|**Aspect**|**Bits**|**Frames**|**Packets**|
|---|---|---|---|
|**Layer**|Physical Layer (Layer 1)|Data Link Layer (Layer 2)|Network Layer (Layer 3)|
|**Purpose**|Transmit raw binary data (0s/1s)|Ensure **hop-to-hop delivery** between directly connected nodes|Route data **source-to-destination** across networks|
|**Structure**|Unstructured binary stream|Header + Payload + Trailer (e.g., CRC)|Header + Payload (IP addresses, TTL)|
|**Addressing**|None|MAC addresses (e.g., `07:01:02:01:2C:4B`)|Logical addresses (e.g., IPv4/IPv6)|
|**Error Handling**|None|CRC checksum in trailer|Relies on higher layers (e.g., TCP)|

### **2.2 The OSI Model**  

- **OSI**: An ISO(International Standards Organization that covers all aspects of network communication - Open Systems Interconnection model (7-layer framework).  
- **Layers and Functions** (Figure 2.2):  
  1. **Physical Layer**: Transmits raw bits over a medium. Responsible for movements of individual bits from node to the next (e.g., cables, electrical signals).  
  2. **Data Link Layer**: Ensures hop-to-hop(node-to-node) frame delivery (e.g., MAC addresses, error detection).  
  3. **Network Layer**: Routes packets between source and destination (e.g., IP addresses).  
  4. **Transport Layer**: Manages end-to-end message delivery (e.g., TCP/UDP, segmentation).  
  5. **Session Layer**: Responsible for Dialogue controls (sessions) and synchroniszation between devices (e.g., synchronization).  
  6. **Presentation Layer**: Translates, encrypts, and compresses data (e.g., SSL, ASCII to binary).  
  7. **Application Layer**: Provides user services (e.g., HTTP, FTP, email).

- **Encapsulation**: Data is wrapped with headers/trailers at each layer (Figure 2.4).
  - **Encapsulation Flow**:  
    Transport Layer **Segment** → Network Layer **Packet** → Data Link Layer **Frame** → Physical Layer **Bits**.

### **2.3 TCP/IP Protocol Suite**  
- **Layers** (Figure 2.16):  
  1. **Physical & Data Link**: Combines OSI’s physical and data link layers (e.g., Ethernet, Wi-Fi).  
  2. **Network (Internet)**: Uses IP for logical addressing and routing.  
  3. **Transport**: Manages process-to-process communication (TCP for reliability, UDP for speed).  
  4. **Application**: Merges OSI’s application, presentation, and session layers (e.g., HTTP, SMTP).
     ![[Pasted image 20250306014807.png|560]]  

- **Key Protocols**:  
  - **Network Layer**: IP, ICMP, ARP.  
  - **Transport Layer**: TCP, UDP, SCTP.  
  - **Application Layer**: HTTP, DNS, FTP.  

---

### **2.4 Addressing in TCP/IP**  
Four levels of addresses in an internet employing TCP/IP protocols (Figure 2.17):  
1. **Physical Address** (MAC):  
   - 48-bit(6-byte) unique identifier for devices (e.g., `07:01:02:01:2C:4B`).
   - Is written as 12 hexadecimal digits. Every 2 bit is separated by a colon.
   - Changes at each hop (e.g., router to router).  
2. **Logical Address** (IP):  
   - 32-bit (IPv4) or 128-bit (IPv6) address (e.g., `192.168.1.1`).  
   - Remains constant from source to destination.  
3. **Port Address**:  
   - 16-bit identifier for processes (e.g., port `80` for HTTP).  
   - Ensures correct delivery to applications.  
4. **Specific Address**:  
   - Application-specific (e.g., email address, URL).
