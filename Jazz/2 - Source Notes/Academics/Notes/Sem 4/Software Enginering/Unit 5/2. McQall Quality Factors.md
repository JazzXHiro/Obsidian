# McQall Quality Factors

![[Pasted image 20250515064656.png]]

## Product Operation (McCall Model)

**Focus**: Requirements affecting software operation, performance, and user experience.  

### Quality Factors:  
- **Correctness**: Meets specifications and user expectations.  
- **Efficiency**: Optimal resource utilization.  
- **Integrity**: Security and data protection.  
- **Reliability**: Consistent performance under conditions.  
- **Usability**: Ease of use and learning.

#### 1. Correctness  
- **Definition**: Software behaves as specified in requirements (e.g., navigation, calculations).  
- **Example**:  
  - *Expected*: After sign-up, user should see terms & conditions page.  
  - *Actual*: User lands on home page → **incorrect behavior**.  

#### 2. Efficiency  
- **Definition**: Optimal use of system resources (CPU, memory).  
- **Example**:  
  - Video editor freezes the system → **poor efficiency** (disrupts other apps).

#### 3. Integrity  
- **Definition**: Prevents unauthorized access to data/software.  

#### 4. Reliability  
- **Definition**: Software performs as expected under maximum load.  
- **Example**:  
  - E-commerce site should auto-failover to another server if one crashes.  

#### 5. Usability  
- **Definition**: Intuitive and user-friendly design.  
- **Example**:  
  - Return option should be clearly visible on orders page (not hidden in "Contact Us").

## Product Revision (McCall Model)

**Focus**: Ensures software can be easily maintained, adapted, and tested over time.  

### Quality Factors:  
- **Maintainability**: Ease of updating/modifying software to fix issues or adapt to changes.  
- **Flexibility**: Ability to adapt to current/future technology demands.  
- **Testability**: Ease of manual testing and defect logging by QA. Ease of test automation.


## Product Transition (McCall Model)  

### Quality Factors:  

### Portability  
- **Definition**: Ability to run on different platforms without major changes.  
- **Example**: Web app works on Android but fails on iOS → **portability issue**.  

### Reusability  
- **Definition**: Degree to which components can be reused across applications.  
- **Example**: Developing sign-in/sign-up forms twice for two apps → **lack of reusability**.  

### Interoperability  
- **Definition**: Ability to exchange data between different systems (OS, DBs, protocols).  
- **Example**: Payment gateway integration fails due to API standard mismatches → **interoperability problem**.
