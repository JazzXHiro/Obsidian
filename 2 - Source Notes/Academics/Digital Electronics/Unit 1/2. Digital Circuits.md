# 2. Digital Circuits

---

## 📘 **Digital Circuits Notes**

### 🔹 1. **Introduction to Digital Circuits**

- **Definition**: Digital circuits process discrete signals—typically binary values (0 and 1)—to perform logical operations, data storage, and control tasks.
    
- **Applications**: Microprocessors, memory devices, digital communication systems, control systems, embedded systems, consumer electronics.
    


---

## 🔹**Essential characteristics of Digital circuits:** 

• Digital circuits use transistors to create logic gates to perform Boolean logic. 

• This logic is the foundation of digital electronics and computer processing. 

• Digital circuits are less susceptible to noise or degradation in quality than analog circuits.

### 🔹 2. **Number Systems and Codes**

![[Pasted image 20250531100047.png||600]]

1. **Binary (Base-2)**
    
    - Digits: 0, 1
        
    - Conversion:
        
        - To decimal: sum of bits × 2^position.
            
        - From decimal: divide by 2, record remainders.
            
2. **Octal (Base-8) & Hexadecimal (Base-16)**
    
    - Octal digits: 0–7; group binary bits in threes.
        
    - Hex digits: 0–9, A–F; group binary bits in fours.
        
3. **Weighted Codes**
    
    - **BCD (Binary-Coded Decimal)**: Each decimal digit represented by 4 bits (0000 to 1001).
        
    - **Excess-3**, **Gray Code** (reflected binary, one-bit change between successive values).
        
4. **Code Conversion**
    
    - Binary ↔ Octal: Group binary in 3 bits.
        
    - Binary ↔ Hex: Group binary in 4 bits.
        
    - Decimal ↔ BCD: Convert decimal digit-by-digit to 4-bit binary.

### 🔹 3. **Boolean Algebra Fundamentals**

1. **Basic Operations**
    
    - **AND ( · )**
        
        - A · B = 1 only if A = 1 and B = 1.
            
    - **OR ( + )**
        
        - A + B = 1 if A = 1 or B = 1 (or both).
            
    - **NOT ( ̅ )**
        
        - A ̅ = 1 if A = 0; A ̅ = 0 if A = 1.
            
2. **Laws and Properties**
    
    - **Commutative**: A + B = B + A; A · B = B · A.
        
    - **Associative**: (A + B) + C = A + (B + C); (A · B) · C = A · (B · C).
        
    - **Distributive**: A · (B + C) = A·B + A·C; A + (B·C) = (A + B)·(A + C).
        
    - **Identity**: A + 0 = A; A · 1 = A.
        
    - **Null (Dominance)**: A + 1 = 1; A · 0 = 0.
        
    - **Idempotent**: A + A = A; A · A = A.
        
    - **Complement**: A + A ̅ = 1; A · A ̅ = 0.
        
    - **De Morgan’s Theorems**:
        
        - (A · B) ̅ = A ̅ + B ̅
            
        - (A + B) ̅ = A ̅ · B ̅
            
3. **Boolean Function Representation**
    
    - **Sum of Products (SOP)**: OR of AND terms.
        
    - **Product of Sums (POS)**: AND of OR terms.
        
    - **Truth Table**: Enumerates output for all possible input combinations.
        
    - **Logic Diagram**: Gate-level realization of a Boolean function.

### 🔹 4. **Basic Logic Gates**

| Gate     | Boolean Expression      | Truth Table Outputs (A, B) |
| -------- | ----------------------- | -------------------------- |
| **AND**  | Y = A · B               | 00→0, 01→0, 10→0, 11→1     |
| **OR**   | Y = A + B               | 00→0, 01→1, 10→1, 11→1     |
| **NOT**  | Y = A̅                  | 0→1, 1→0                   |
| **NAND** | Y = (A · B)̅            | 00→1, 01→1, 10→1, 11→0     |
| **NOR**  | Y = (A + B)̅            | 00→1, 01→0, 10→0, 11→0     |
| **XOR**  | Y = A ⊕ B = A·B̅ + A̅·B | 00→0, 01→1, 10→1, 11→0     |
| **XNOR** | Y = (A ⊕ B)̅            | 00→1, 01→0, 10→0, 11→1     |

	- **Universal Gates**: NAND and NOR can implement any Boolean function (useful for standardized IC manufacturing).`

### 🔹 5. **Combinational Logic Circuits**

- **Definition**: Output depends only on the current inputs (no memory or feedback).
    
- **Design Procedure**:
    
    1. **Specification**: Define the problem, inputs, outputs, and functional requirements.
        
    2. **Truth Table**: List all input combinations and corresponding outputs.
        
    3. **Boolean Expression**: Derive minimal SOP or POS form using simplification (Boolean algebra, Karnaugh maps).
        
    4. **Logic Diagram**: Draw gate-level implementation.
        
    5. **Optimization**: Minimize gate count, levels, and propagation delay.
        

#### 5.1 **Karnaugh Map (K-Map) Simplification**

- **Setup**:
    
    - For _n_ variables, create a 2^n-cell grid.
        
    - Fill with 1’s where function is true (for SOP); 0’s for POS.
        
- **Grouping**:
    
    - Form groups of 1, 2, 4, 8, … cells (powers of two), covering all 1’s with as few groups as possible.
        
    - Allow overlaps and wrap-around edges.
        
- **Extract Simplified Terms**:
    
    - Each group corresponds to a product term with variables that remain constant within that group.
        
    - Combine all group terms (OR) for minimal SOP.
        

#### 5.2 **Common Combinational Building Blocks**

1. **Multiplexer (MUX)**
    
    - Selects one of many inputs.
        
    - **2-to-1 MUX**: Y = S̅·A + S·B (S = select).
        
    - **4-to-1 MUX**, **8-to-1 MUX**, etc.
        
2. **Demultiplexer (DEMUX)**
    
    - Routes a single input to one of many outputs based on select lines.
        
3. **Decoder / Encoder**
    
    - **Decoder**: n-to-2^n lines. If input = k, output k-th line is HIGH; others LOW.
        
    - **Encoder**: Reverse of decoder; compress multiple input lines to binary code.
        
4. **Priority Encoder**
    
    - When multiple inputs are active, outputs the code of the highest-priority input.
        
5. **Adder / Subtractor**
    
    - **Half Adder**: Sum = A ⊕ B; Carry = A · B.
        
    - **Full Adder**: Sum = A ⊕ B ⊕ Cin; Cout = A·B + B·Cin + A·Cin.
        
    - **Ripple Carry Adder**: Cascade full adders; slower due to carry propagation.
        
    - **Look-Ahead Carry Adder**: Generates carries in parallel for faster operation.
        
6. **Comparator**
    
    - Compares two binary numbers; outputs “A > B,” “A = B,” “A < B.”
        
7. **Arithmetic Logic Unit (ALU)**
    
    - Combines arithmetic (add, subtract) and logic (AND, OR, XOR) operations; fundamental block in CPUs.

### 🔹 6. **Minimization Techniques**

1. **Boolean Algebra Simplification**
    
    - Apply laws (e.g., De Morgan’s, distributive) to reduce terms.
        
    - Manual and suitable for small functions (≥3 variables can be tedious).
        
2. **Karnaugh Map (K-Map)**
    
    - Visual technique for up to 4–6 variables (practical limit is 4 for hand-solving; 5–6 if careful).
        
3. **Quine–McCluskey Method (Tabulation)**
    
    - Systematic algorithm for larger number of variables.
        
    - Steps:
        
        - List minterms (in binary).
            
        - Group by number of ones.
            
        - Compare adjacent groups, form implicants, mark used.
            
        - Repeat until no further combinations.
            
        - Create prime implicant chart; select essential prime implicants; cover remaining minterms.

### 🔹 7. **Sequential Logic Circuits**

- **Definition**: Output depends on current inputs _and_ past history (memory). Incorporate feedback loops.
    
- **Clocked** vs **Asynchronous**:
    
    - **Clocked (Synchronous)**: Changes occur only at discrete clock events (edges). Easier to design and time.
        
    - **Asynchronous**: Changes occur immediately when inputs change. Faster but prone to hazards and glitches.
        

#### 7.1 **Basic Storage Elements**

1. **Latch**
    
    - **SR (Set–Reset) Latch** (level-sensitive):
        
        - Inputs: S, R; Outputs: Q, Q̅.
            
        - Truth Table:
            
            |S|R|Q(next)|Comment|
            |---|---|---|---|
            |0|0|Q(prev)|Hold|
            |0|1|0|Reset|
            |1|0|1|Set|
            |1|1|—|Invalid/Race|
            
    - **D (Data) Latch**:
        
        - Single data input D, clock enable (en).
            
        - When en = 1, Q = D; when en = 0, Q holds previous value.
            
2. **Flip-Flop** (edge-triggered)
    
    - Triggered on clock’s rising or falling edge.
        
    - **Types**:
        
        - **SR Flip-Flop**: Edge-sensitive version of SR latch; same truth table (except for invalid condition).
            
        - **D Flip-Flop**:
            
            - Ideal memory element. Q(next) = D at the triggering clock edge.
                
            - No invalid state.
                
        - **JK Flip-Flop**:
            
            - Inputs J, K; toggles when J=K=1.
                
            - Combines SR with no invalid condition.
                
        - **T (Toggle) Flip-Flop**:
            
            - Single input T; if T=1, toggles output; if T=0, holds.
                

#### 7.2 **Flip-Flop Timing Parameters**

- **Setup Time (tsu)**: Minimum time before clock edge that input must be stable.
    
- **Hold Time (th)**: Minimum time after clock edge that input must remain stable.
    
- **Propagation Delay (tpd)**: Time from clock edge to output valid.
    
- **Clock-to-Q Delay (tCQ)**: Delay from clock edge to Q output.

### 🔹 8. **Registers and Counters**

1. **Registers**
    
    - Group of flip-flops sharing a clock.
        
    - **Types**:
        
        - **Parallel-Load Register**: Load N-bit data in parallel on clock edge.
            
        - **Shift Register**:
            
            - **SISO (Serial-In Serial-Out)**
                
            - **SIPO (Serial-In Parallel-Out)**
                
            - **PISO (Parallel-In Serial-Out)**
                
            - **PIPO (Parallel-In Parallel-Out)**
                
        - **Bidirectional Shift Register**: Can shift left or right.
            
    - **Applications**: Data storage, data transfer, serial-to-parallel and parallel-to-serial conversion.
        
2. **Counters**
    
    - A specialized register that cycles through a predetermined sequence of states.
        
    - **Asynchronous (Ripple) Counter**:
        
        - Flip-flops triggered by output of preceding stage.
            
        - Simple but prone to propagation delay accumulation.
            
    - **Synchronous Counter**:
        
        - All flip-flops triggered by same clock.
            
        - No ripple; faster and predictable timing.
            
    - **Up/Down Counter**: Counts up, down, or in Gray code.
        
    - **Modulo-n Counter**: Cycles through n states (e.g., mod-10 decade counter).
        
    - **Johnson Counter** and **Ring Counter**: Shift registers with feedback for specific state sequences.

### 🔹 9. **Finite State Machines (FSM)**

1. **Definitions**
    
    - **States**: Unique configurations.
        
    - **Transitions**: Movement between states based on inputs/clock.
        
    - **MOORE vs MEALY**:
        
        - **Moore**: Output depends only on current state.
            
        - **Mealy**: Output depends on current state and inputs.
            
2. **Design Steps**
    
    1. **Problem Specification**: Define inputs, outputs, and required behavior.
        
    2. **State Diagram**: Graphical representation of states and transitions.
        
    3. **State Table**: Tabulate present state, inputs, next state, outputs.
        
    4. **State Assignment**: Assign binary codes to each state.
        
    5. **Derive Excitation and Output Equations**: Using flip-flop characteristic equations.
        
    6. **Draw Logic Diagram**: Implement using gates and flip-flops.
        
    7. **Optimize**: Minimize number of states, transitions, or logic complexity if feasible.

### 🔹 10. **Timing Analysis and Hazards**

1. **Propagation Delay (t_pd)**: Gate input-to-output delay.
    
2. **Contamination Delay (t_cd)**: Shortest time from input change to output change.
    
3. **Setup and Hold for Sequential Circuits**:
    
    - Ensure each flip-flop’s data input meets tsu and holds through th relative to clock edge.
        
4. **Maximum Clock Frequency (f_max)**:
    
    - f_max ≤ 1 / (t_cq + t_pd,combinational + t_su)
        
    - t_cq = clock-to-Q delay of source flip-flop; t_pd,combinational = worst-case delay through combinational logic.
        
5. **Hazards**
    
    - **Static-1 Hazard**: Output should remain 1 but glitch to 0 briefly due to different path delays.
        
    - **Static-0 Hazard**: Output should remain 0 but glitch to 1.
        
    - **Dynamic Hazard**: Multiple transitions (0→1→0 or 1→0→1).
        
    - **Elimination**: Add redundant covering terms in Boolean expression or ensure hazard-free gate implementation.

### 🔹 11. **Medium-Scale Integration (MSI) and Large-Scale Integration (LSI) Components**

1. **Timers**
    
    - **555 Timer IC**: Used in monostable, astable modes. Generates pulses, oscillations.
        
2. **Counters**
    
    - **74xx Series**:
        
        - 74LS90: Decade counter.
            
        - 74LS161: Synchronous 4-bit binary counter.
            
3. **Shift Registers**
    
    - **74xx164**: 8-bit serial-in, parallel-out shift register.
        
    - **74xx299**: Universal shift register (parallel/serial).
        
4. **Multiplexers / Demultiplexers**
    
    - **74xx151**: 8-to-1 MUX.
        
    - **74xx138**: 3-to-8 decoder.
        
5. **Memory Elements**
    
    - **SRAM**, **DRAM** chips—arranged in arrays, addressed via decoders.

### 🔹 12. **Introduction to Hardware Description Languages (HDL)**

- **Verilog** and **VHDL** allow modeling of digital circuits at various abstraction levels:
    
    1. **Behavioral**: Algorithmic description (e.g., always blocks in Verilog).
        
    2. **Dataflow**: Uses continuous assignments (assign keyword).
        
    3. **Structural**: Instantiates gates and modules explicitly.
        
- **Basic Verilog Constructs**:
    
    - **module** declaration, **input/output** ports, **wire** / **reg** types.
        
    - **always @ (posedge clk)** for sequential logic.
        
    - **assign** statements for combinational logic.

### 🔹 13. **Design Methodology**

1. **Specification**: Functional requirements, input/output definitions, performance constraints (speed, power, area).
    
2. **Behavioral Modeling**: High-level description (HDL) to simulate intended behavior.
    
3. **RTL (Register-Transfer Level) Design**: Detailed HDL describing data flow between registers and combinational logic.
    
4. **Synthesis**: Convert RTL into gate-level netlist (tool-based).
    
5. **Simulation and Verification**:
    
    - **Functional Simulation**: Verify correct logic.
        
    - **Timing Simulation**: Include gate delays, check setup/hold.
        
6. **Implementation**:
    
    - **FPGA**: Place-and-route, bitstream generation.
        
    - **ASIC**: Logic synthesis, placement, routing, fabrication.
        
7. **Testing and Validation**: On-target hardware testing (test vectors, boundary scan, logic analyzers).

### 🔹 14. **Common Pitfalls and Best Practices**

- **Glitches and Hazards**: Always verify using timing analysis; add redundant terms if necessary.
    
- **Metastability**: When asynchronous inputs feed flip-flops, use synchronization stages.
    
- **Fan-in / Fan-out Constraints**: Each gate can only drive a limited number of inputs; buffer if exceeded.
    
- **Ground Bounce and Power Noise**: Decouple power rails with capacitors; use proper PCB layout techniques.
    
- **Clock Skew**: Route clock carefully; consider using clock distribution networks or PLLs/DCMs for balancing.
    
- **Reset Strategy**: Define synchronous vs. asynchronous reset; ensure reliable reset at power-up.
    

---

## 📝 **Key Takeaways**

- **Combinational vs Sequential**: Combinational depends solely on inputs; sequential includes memory and state elements (flip-flops, latches).
    
- **Boolean Minimization**: Crucial for reducing gate count and improving speed; use K-map or Quine–McCluskey for systematic simplification.
    
- **Clocked Systems**: Timing constraints (setup, hold) and propagation delays dictate maximum operating frequency.
    
- **Modular Design**: Build complex systems by combining MSI/LSI blocks (e.g., MUXes, counters, decoders) and verify each module before integration.
    
- **HDL & EDA Tools**: Learning Verilog or VHDL streamlines design, simulation, and synthesis for real-world digital systems.
