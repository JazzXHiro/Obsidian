# ARP & RARP


### 📌 **1. What is ARP (Address Resolution Protocol)?**

- **Purpose**: Maps an **IP address** (logical address) to a **MAC address** (physical address).
    
- **Used By**: Hosts and routers in a **LAN** to find the MAC address of a device with a known IP address.
    

#### 🔄 **How ARP Works**

1. A device wants to send a packet to a known IP address on the local network.
    
2. It checks its ARP cache. If the MAC is unknown:
    
3. It broadcasts an **ARP Request**: "Who has IP X.X.X.X?"
    
4. The device with that IP replies with its **ARP Reply**: "I have that IP, and my MAC is XX:XX:XX:XX."
    

#### 📂 **ARP Table (Cache)**

- Temporarily stores IP-to-MAC mappings.
    
- Reduces the need for repeated ARP broadcasts.
    

#### 📌 **ARP Packet Fields**

- Hardware type (Ethernet)
    
- Protocol type (IPv4)
    
- Hardware size (MAC length)
    
- Protocol size (IP length)
    
- Operation (request or reply)
    
- Sender MAC & IP
    
- Target MAC & IP
    

---

### 🔁 **2. What is RARP (Reverse Address Resolution Protocol)?**

- **Purpose**: Maps a **MAC address** to an **IP address**.
    
- **Used By**: Diskless workstations that know their MAC but not their IP.
    

#### 🔄 **How RARP Works**

1. A diskless device sends a RARP request to a RARP server.
    
2. The server looks up the IP address mapped to the MAC.
    
3. It sends a RARP Reply containing the IP address.
    

> 🔴 **Note**: RARP is obsolete. It has been replaced by more modern protocols like **BOOTP** and **DHCP**.

---

### ⚖️ **Comparison Table: ARP vs RARP**

|Feature|ARP|RARP|
|---|---|---|
|Purpose|IP → MAC|MAC → IP|
|Used by|All devices|Diskless devices|
|Packet direction|Broadcast request, unicast reply|Broadcast request, unicast reply|
|Protocol type|Dynamic address resolution|Static mapping (from server)|
|Status|Widely used|Obsolete, replaced by DHCP/BOOTP|
