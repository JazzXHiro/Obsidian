# 📘 Lexical Analyzer (First Phase of Compiler Design)

## 1️⃣ Definition

The **Lexical Analyzer** is the **first phase of compiler design**.

Its main task is:

> To identify the valid words (tokens) in the input program of the language being considered.

It works independently of formatting such as:

- Spaces
    
- Indentation
    
- Line breaks
    

Formatting does not affect lexical analysis.

---

## 2️⃣ Two Main Processes

Lexical analysis is generally divided into a cascade of two processes:

### 1. Scanning

### 2. Lexical Analysis (Token Generation)

### Flow:

```
Input Program → Scanning → Lexical Analysis → Tokens
```

---

## 3️⃣ Scanning

- Reads the input program character by character.
    
- Removes:
    
    - White spaces
        
    - Comments
        
- Groups characters into meaningful sequences.
    

---

## 4️⃣ Lexical Analysis Proper

- Converts sequences of characters into **tokens**.
    
- Produces tokens for the parser.
    

Example:

```
int a = 10;
```

Tokens:

```
int | a | = | 10 | ;
```

---

## 5️⃣ Tokens

A **token** is a valid word of a programming language.

Examples:

- Keywords → `int`, `float`
    
- Identifiers → `a`, `sum`
    
- Operators → `+`, `=`
    
- Constants → `10`, `5.5`
    

---

## 6️⃣ Interaction with Parser

From your diagram:

```
Lexical Analysis  →  Parser
        ↑               ↓
     Symbol Table
```

### Working:

- Parser calls the lexical analyzer using:
    
    ```
    getNextToken()
    ```
    
- Lexical analyzer returns the next token.
    
- This continues until end of file.
    

---

## 7️⃣ Symbol Table

The lexical analyzer and parser both interact with the **Symbol Table**.

### Symbol Table Stores:

- Variable names
    
- Keywords
    
- Identifiers
    
- Memory references
    

When a new identifier is found:

- It is entered into the symbol table.
    

---

## 8️⃣ Complete Working Flow (Based on Your Page)

1. Input program is given.
    
2. Scanning removes unnecessary formatting.
    
3. Lexical analyzer generates tokens.
    
4. Tokens are passed to the parser.
    
5. Parser repeatedly requests next token.
    
6. Symbol table stores identifiers and related information.
    

---

# 🎯 Important Points for Exam

- Lexical Analyzer is the **first phase** of compiler.
    
- Produces **tokens**.
    
- Ignores formatting like spaces and indentation.
    
- Works closely with:
    
    - Parser
        
    - Symbol Table
        
- Parser uses `getNextToken()` to obtain tokens.
