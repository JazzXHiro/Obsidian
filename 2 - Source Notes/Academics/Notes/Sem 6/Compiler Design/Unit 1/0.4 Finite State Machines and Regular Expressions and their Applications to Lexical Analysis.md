# Finite State Machines and Regular Expressions and their Applications to Lexical Analysis

## Lexical Analyzer

First phase of compiler design. The task of lexical analyzer phase is to identify the valid words that we have in the $i/p$ program for the language that we are considering which should be independent of formatting(or indentation) generally. Lexical Analyzers is divided into cascade of two processes.

### Two Main Processes

#### 1. Scanning

- Reads the input program character by character.
    
- Removes:
    
    - White spaces
        
    - Comments
- Groups characters into meaningful sequences.

```
+-------------+     +-----------+     +-------------------+     +--------+
|   Input     | --> | Scanning  | --> | Lexical Analysis  | --> | Tokens |
|   Program   |     |           |     |                   |     |        |
+-------------+     +-----------+     +-------------------+     +--------+
```
#### 2. Lexical Analysis(Token Generation)

- Converts sequences of characters into **tokens**.
  
- Produces tokens for the parser.

##### [[0.2 The Structure of a Compiler#^143883|Token]]
A pair comprising of token name and and an optional token value.
**Examples:**

- Keywords → `int`, `float`
    
- Identifiers → `a`, `sum`
    
- Operators → `+`, =
    
- Constants → `10`, `5.5`

![[0.4 Finite State Machines and Regular Expressions and their Applications to Lexical Analysis 2026-02-22 18.17.10.excalidraw|500]]

##### Lexeme
A sequence of $i/p$ characters that comprises of a single token.

**Example-**

```cpp
#include <stdio.h>

int main()
	{
	printf("HELLO WORLD");
	return 0;
	}
```

$$\#include<stdio.h>\text{intmain()}\{\text{printf("HELLOWORLD");return0;}\}$$

##### Pattern
A description of the form that Lexeme of a token may take.


> [!NOTE] Extra
> Lexeme are also defined as sequence of characters in the source program that matches the pattern of token.

###### Types of Tokens

1. **Keywords**
   - Reserved words.
   - Have predefined meaning.
   - Cannot be used as identifiers.
   - Example:`if, else, while, int, float, return, for`
   - Token form: `<KEYWORD>`

2. **Identifiers**
   - Names given by programmers
   - Used for variables, functions, arrays etc.
   - Usually: letter followed by letters and digits.
   - Examples: `a, sum, totalMarks, pi`
   - Token form: `ID, pointer_to_symbol_table`

3. **Constants (Literals)**
   - Integer constants, floating constants, character constants, string literals.
   - Token form: 
	     `<NUMBER>`
	     `<STRING>`
	     `<CHAR>`

3. **Operators**
   - Symbols that perform operations
   - Arithmetic Operators `+ - * / %`
   - Relational Operators `< > <= >= == !=`
   - Logical Operators `&& || !`]
   - Assignment Operators =
   - Token form:
     `<ADD_OP>`
     `<MUL_OP>`
     `<REL_OP>`
     `<ASSIGN_OP>`

3. **Separators / Delimiters (Punctuators)**
   - Used to separate program elements.
   - Examples: `; , ( ) { } [ ]`
   - Token form:
     `<SEMICOLON>`
     `<LBRACE>`
     `<RBRACE>`


> [!NOTE] Note
> Generally when we generate a token, it is presented in triangular brackets (<>).

##### Example of token generation

$$E = mc^2$$

|Lexeme|Token Generated|Meaning|
|---|---|---|
|E|`<id>`|Pointer to symbol table entry for E|
|=|`<assign_op>`|Assignment operator|
|m|`<id>`|Pointer to symbol table entry for m|
|*|`<mul_op>`|Multiplication operator|
|C|`<id>`|Pointer to symbol table entry for C|
|**|`<exp_op>`|Exponential operator|
|2|`<number>`|Integer constant value 2|
**Lexical Output:**
```
<id, ptr_to_E>
<assign_op>
<id, ptr_to_m>
<mul_op>
<id, ptr_to_C>
<exp_op>
<number, 2>
```

> [!NOTE] Note
> Finite Automata is used in the Lexical Analysis phase to recognize whether a sequence of characters forms a valid token.

### Lexical Error

A lexical error is an error that occurs when the lexical analyzer (scanner) encounters a sequence $i/o$ characters that does not match any valid token pattern of the programming language.

#### Examples of Lexical Errors

##### 1. Invalid Identifier
```
int 2value;
```
**Reason:**
- Identifier cannot start with a digit.

##### 2. Invalid Symbol
```
int a = 5 @ 3;
```
**Reason:**
- `@` is not a valid operator in C.

##### 3. Unterminated String
```
printf("Hello);
```
**Reason:**
- Missing closing double quote.

##### 4. Illegal Character
```
int a = 5 ₹ 3;
```
**Reason:**
- `₹` is not part of language character set.

#### Panic Recovery Mode
Errors are recognized when no pattern for tokens matches a character sequence.
