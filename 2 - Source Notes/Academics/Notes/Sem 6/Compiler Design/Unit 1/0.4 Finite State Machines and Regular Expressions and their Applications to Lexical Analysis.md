# Finite State Machines and Regular Expressions and their Applications to Lexical Analysis

## Lexical Analyzer

First phase of compiler design. The task of lexical analyzer phase is to identify the valid words that we have in the $i/p$ program for the language that we are considering which should be independent of formatting(or indentation) generally. Lexical Analyzers is divided into cascade of two processes.

### Two Main Processes

#### 1. Scanning

- Reads the input program character by character.
    
- Removes:
    
    - White spaces
        
    - Comments
- Groups characters into meaningful sequences.

```
+-------------+     +-----------+     +-------------------+     +--------+
|   Input     | --> | Scanning  | --> | Lexical Analysis  | --> | Tokens |
|   Program   |     |           |     |                   |     |        |
+-------------+     +-----------+     +-------------------+     +--------+
```
#### 2. Lexical Analysis(Token Generation)

- Converts sequences of characters into **tokens**.
  
- Produces tokens for the parser.

##### [[0.2 The Structure of a Compiler#^143883|Token]]
A pair comprising of token name and and an optional token value.
**Examples:**

- Keywords → `int`, `float`
    
- Identifiers → `a`, `sum`
    
- Operators → `+`, =
    
- Constants → `10`, `5.5`

##### Lexeme
A sequence of $i/p$ characters that comprises of a single token.

**Example-**

```cpp
#include <stdio.h>

int main()
	{
	printf("HELLO WORLD");
	return 0;
	}
```
