# 0.2 The Structure of a Compiler

> There are two parts to the mapping of the source program to a semantically equivalent target program - 
> i) analysis              and              (ii) synthesis

![[0.2 The Structure of a Compiler 2026-01-20 19.45.54.excalidraw||800]]


> [!NOTE] Analysis and Synthesis
> 
> **Analysis** - The analysis part breaks up the source into it's constituent parts and imposes a grammatical structure on them. It then utilizes that structure to create an intermediate representation of the source program. If the analysis part concludes that any part of the source code is syntactically or semantically wrong, it needs to send a message to the user for the appropriate corrective action. The analysis part also collects the information about the source program and stores it in a data structure called the Symbol table, which is then passed along to the synthesis part along with the Symbol table. It is often referred to as the front-end of the compiler.
> 
> **Synthesis** - The synthesis part creates the the target program from the intermediate representation and the information from the symbol table. It is often referred to as the back end of the compiler.

>**Machine Independent Code Optimizer -** It is done between the front end and back end part. It helps in transforming the intermediate representation in a such a manner that it produces better target program.
>

## 1. Lexical Analysis

It is the first phase of the compiler. Also referred to as ***scanning***. The lexical analyzer reads the streams of the characters from the source program and group the characters into semantic sequences called **lexemes**. For each lexeme, the lexical analyzer produces tokens as output of the form -

$$<token-name,attribute-value>$$

- $token - name:$ The first component *token-name* is an abstract symbol that is used during syntax analysis.

- $attribute - value:$ Points to an entry in the symbol table for this token.

> Information from the Symbol Table is needed for Semantic Analysis and Code Generation.

## 2. Syntax Analysis

It's the seconds phase of the compiler, also called parsing. The parser utilizes the tokens from the Lexical Analyzer to create an intermediate tree-like representation that depicts the grammatical structure of the token stream. A typical representation is a syntax tree in which each interior node represents an operation and each children node represent the argument of the operation. It is shown in the figure above.

## 3. Semantic Analysis

It uses the syntax tree and the information from the symbol table to check the source program for semantic consistency with the language definition. It also collects type information and stores it into the syntax tree or symbol table, for subsequent use during intermediate-code generation.

**Type checking** is an important part of semantic analysis, where the compiler checks that each operator has a matching operands. For ex:- many programming language definitions require an array of an index to be of integer type; the compiler must report an error if it comes across a floating point number that is for index of an array.

**Coercions** are specific type conversions that maybe permitted by language specifications. For example, a binary arithmetic operator may be applied to either a pair of integers or to a pair of floating-point numbers. If the operator is applied to a floating-point number and an integer, the compiler may convert or coerce the integer into a floating-point number. Such a coercion happens in the figure above.

## 4. Intermediate Code Generation

In the process of translating a source program into target code, a compiler constructs one or more intermediate representations. They can have a variety of forms. Syntax tree are a type of intermediate representation, they are utilized during syntax and semantic analysis.

Many compilers after syntax and semantic analysis generate an explicit low-level or machine-like intermediate representation. This intermediate representation should have two important properties: it should be easy to produce and it should be easy to translate into the target machine.

In the above figure three-address code is utilized which consists of assembly-like instructions with three operands per instructions. Each operand can act like register.

There are several points worth noting about the three-address assignment. First, each three-address assignment instruction has at most one operator on the right side. Thus, these instructions fix the order in which operations are to be done; the multiplication precedes the addition in the source program. Second, the compiler must generate a temporary name to hold the value computed by a three-address instruction. Third, some "three-address instructions" like the first and the last in the sequence, above have fewer than three operands.

## 5. Code Optimization

This phase attempts to improve the intermediate code so that better target code will result. Usually better mean faster, but other objectives may be desired, such as shorter code, or target code that consumes less power.
