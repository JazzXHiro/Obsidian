### Q1. Explain the role of the Key Distribution Center (KDC) in the Kerberos authentication protocol.

The **Key Distribution Center (KDC)** is the central trusted authority in the Kerberos protocol. Its primary role is to manage secret keys and authenticate users without storing passwords in plain text or transmitting them over the network.

- **Structure:** It consists of two logical parts: the **Authentication Server (AS)** and the **Ticket Granting Server (TGS)**.
    
- **Function:** It authenticates the client at login and issues a "Ticket Granting Ticket" (TGT). When the user wants to access a specific service (like a file server), the KDC issues a specific service ticket and a session key, allowing the two parties to communicate securely without knowing each other's long-term passwords. This reduces the number of keys required in a network from $N(N-1)/2$ to $N$.

|---|---|---|

### Q3. In the MD5 algorithm, the message length is given as 991 bits. Find the number of padding bits required in this case?

MD5 padding ensures the message length is congruent to 448 modulo 512 ($L \equiv 448 \pmod{512}$).

1. **Current Length ($L$):** 991 bits.
    
2. **Modulo Check:** $991 \pmod{512} = 479$.
    
3. Required Padding ($P$): We need to reach the next boundary where the remainder is 448.
    
    Since $479 > 448$, we must go to the next block.
    
    Equation: $479 + P = 512 + 448$
    
    $479 + P = 960$
    
    $P = 960 - 479 = 481$
    

**Answer:** 481 padding bits are required (consisting of a single '1' followed by 480 '0's).

### Q4. Solve the quadratic congruence $x^{2}\equiv9 \pmod{17}$. What are the solutions?

1. We are looking for a number $x$ such that when squared and divided by 17, the remainder is 9.
    
2. $x = \sqrt{9} = \pm 3$.
    
3. **Solution 1:** $x = 3$. ($3^2 = 9$).
    
4. Solution 2: $x = -3$. In modular arithmetic, $-3 \equiv 17 - 3 \equiv 14 \pmod{17}$.
    
    Check: $14^2 = 196$. $196 \div 17 = 11$ with a remainder of $9$.
    

**The solutions are $x = 3$ and $x = 14$.**

### Q5. Discuss the difference between symmetric and asymmetric cryptography.

- **Symmetric Cryptography:** Uses a **single shared secret key** for both encryption and decryption. It is faster and suitable for bulk data (e.g., AES, DES). The main challenge is secure key distribution.
    
- **Asymmetric Cryptography:** Uses a **pair of keys** (Public Key for encryption, Private Key for decryption). It solves the key distribution problem and provides authentication/non-repudiation but is computationally slower (e.g., RSA, ECC).

### Q6. (Option 1) Hill Cipher Decryption Key

Given: $K = \begin{pmatrix} 4 & 7 \\ 2 & 3 \end{pmatrix}$.

Task: Find $K^{-1} \pmod{26}$.

1. Calculate Determinant:
    
    $Det(K) = (4)(3) - (7)(2) = 12 - 14 = -2$.
    
    Modulo 26: $-2 \equiv 24 \pmod{26}$.
    
2. Check Invertibility:
    
    For a key matrix to be invertible in Hill Cipher, the determinant must be coprime to the modulus ($GCD(Det, 26)$ must be 1).
    
    $GCD(24, 26) = 2$.
    
    Since the GCD is not 1, the modular multiplicative inverse of the determinant does not exist.
    
    Therefore, mathematically, this specific key matrix cannot be used for decryption in a standard Hill Cipher over Modulo 26.
    

_(Note: If the question implies ignoring the validity check, the process would be $K^{-1} = Det^{-1} \times \text{adj}(K)$, but $24^{-1} \pmod{26}$ is undefined)._

### Q7. Working of the Feistel Cipher

The Feistel Cipher is a symmetric structure used in many block ciphers (like DES).

- **Structure:** It splits the plaintext block into two halves: Left ($L_0$) and Right ($R_0$).
    
- **Encryption Process (Round $i$):**
    
    1. The Right half ($R_{i-1}$) remains unchanged and becomes the new Left half ($L_i$).
        
    2. The Right half ($R_{i-1}$) also goes through a Round Function ($F$) combined with a subkey ($K_i$).
        
    3. The result of the function is XORed with the old Left half ($L_{i-1}$) to create the new Right half ($R_i$).
        
    
    - Formula:
        
        $L_i = R_{i-1}$
        
        $R_i = L_{i-1} \oplus F(R_{i-1}, K_i)$
        
- **Decryption:** The process is exactly the same as encryption but the subkeys are applied in reverse order. This is a major advantage as it simplifies implementation (hardware/software only needs to implement the encryption logic).
    

### Q8. Discuss the following terms

- **a) Non-repudiation:** A service that prevents an entity from denying previous commitments or actions. (e.g., using digital signatures, a sender cannot deny sending a specific message).
    
- **b) Intruder:** An unauthorized entity (person or program) who attempts to access data, manipulate the system, or disrupt communication (also called an attacker or adversary).
    
- **c) Avalanche Effect:** A desirable property in cryptography (specifically block ciphers and hash functions) where a small change in the input (e.g., flipping 1 bit) results in a drastic change in the output (e.g., changing 50% of the bits).
    
- **d) Authentication:** The process of verifying the identity of a user, device, or system. It ensures the entity is who they claim to be.
    

### Q9. Euclidean Algorithm & Inverse

a) Find multiplicative inverse of 29 mod 392.

We want $x$ such that $29x \equiv 1 \pmod{392}$.

Using Extended Euclidean Algorithm:

1. $392 = 13(29) + 15$
    
2. $29 = 1(15) + 14$
    
3. $15 = 1(14) + 1$ (GCD is 1, so inverse exists)
    

Back-substitution:

$1 = 15 - 1(14)$

$1 = 15 - 1(29 - 1(15))$

$1 = 2(15) - 1(29)$

Substitute 15 from eq 1 ($15 = 392 - 13(29)$):

$1 = 2(392 - 13(29)) - 1(29)$

$1 = 2(392) - 26(29) - 1(29)$

$1 = 2(392) - 27(29)$

This means $-27(29) \equiv 1 \pmod{392}$.

Inverse is $-27$.

Convert to positive: $392 - 27 = 365$.

Multiplicative Inverse = 365.

**b) When multiplicative inverse does not exist.**

- **Scenario:** The inverse of $a \pmod m$ does not exist if $a$ and $m$ are **not coprime**, i.e., $GCD(a, m) \neq 1$.
    
- Example: Find inverse of 2 mod 4.
    
    GCD(2, 4) = 2.
    
    There is no integer $x$ such that $2x \equiv 1 \pmod 4$ (because $2x$ will always be even, and numbers $\equiv 1 \pmod 4$ are always odd).

### Q10. (Option 1) Digital Signature

**Definition:** A digital signature is a cryptographic mechanism used to verify the authenticity and integrity of digital data. It is the digital equivalent of a handwritten signature but is more secure.

**Difference from Handwritten Signature:**

1. **Binding:** A digital signature depends on the content of the message itself (if the message changes, the signature changes). A handwritten signature looks the same regardless of the document.
    
2. **Copying:** Digital signatures cannot be "copied" and pasted to another document because the verification would fail against the new data hash.
    

**Process:**

1. **Creation (Signing):**
    
    - A hash function (e.g., SHA-256) is applied to the message to create a message digest.
        
    - The sender encrypts this digest using their **Private Key**. This encrypted digest is the signature.
        
2. **Verification:**
    
    - The receiver takes the message and applies the same hash function to create a new digest.
        
    - The receiver decrypts the sender's signature using the sender's **Public Key** to reveal the original digest.
        
    - If the calculated digest matches the decrypted digest, the signature is valid.
        

**Role of Keys and Hash:**

- **Hash Function:** Ensures integrity and efficiency (signs a small digest rather than a large file).
    
- **Private Key:** Ensures non-repudiation and authenticity (only the owner could have signed it).
    
- **Public Key:** Allows anyone to verify the signature.
    

### Q10. (Option 2) Diffie-Hellman Key Exchange

Working:

It allows two parties (Alice and Bob) to establish a shared secret over an insecure channel.

1. **Setup:** Agree on a large prime $p$ and a generator $g$.
    
2. **Alice:** Picks private secret $a$. Sends public value $A = g^a \pmod p$.
    
3. **Bob:** Picks private secret $b$. Sends public value $B = g^b \pmod p$.
    
4. **Compute:** Alice calculates $S = B^a \pmod p$. Bob calculates $S = A^b \pmod p$.
    
5. **Result:** Both have $S = g^{ab} \pmod p$.
    

Example:

$p=23, g=5$.

- Alice picks $a=6$. Calculates $5^6 \pmod{23} = 8$. Sends 8.
    
- Bob picks $b=15$. Calculates $5^{15} \pmod{23} = 19$. Sends 19.
    
- Alice computes $19^6 \pmod{23} = 2$.
    
- Bob computes $8^{15} \pmod{23} = 2$.
    
- **Shared Key = 2.**
    

Quantum Analysis:

Diffie-Hellman relies on the Discrete Logarithm Problem (DLP) (finding $a$ given $g^a$).

- **Quantum Safe? No.**
    
- **Reason:** Shor's Algorithm, running on a sufficiently powerful quantum computer, can solve the DLP in polynomial time, effectively breaking Diffie-Hellman.
    

### Q11. S-AES (Simplified AES)

**Given:**

- Plaintext ($P$) = $D728$
    
- Key ($K$) = $4AF5$
    
- S-Box and Tables provided.
    
- $RCON1 = 80$ ($1000 0000_2$), $RCON2 = 30$ ($0011 0000_2$).
    

1. Find Keys $K_1$ and $K_2$

Let Key words be $w_0, w_1$.

$w_0 = 4A, w_1 = F5$.

**Calculate $K_1$ ($w_2, w_3$):**

- $T = RotNib(w_1) = Rot(F5) = 5F$.
    
- $SubNib(5F)$: S-Box(5)=1, S-Box(F)=7. Result = 17.
    
- $w_2 = w_0 \oplus RCON1 \oplus 17 = 4A \oplus 80 \oplus 17$.
    
    - $4A = 0100 1010$
        
    - $80 = 1000 0000$
        
    - $17 = 0001 0111$
        
    - XOR = $1101 1101 = DD$.
        
- $w_3 = w_2 \oplus w_1 = DD \oplus F5$.
    
    - $DD = 1101 1101$
        
    - $F5 = 1111 0101$
        
    - XOR = $0010 1000 = 28$.
        
- **$K_1 = DD28$**
    

**Calculate $K_2$ ($w_4, w_5$):**

- $T = RotNib(w_3) = Rot(28) = 82$.
    
- $SubNib(82)$: S-Box(8)=6, S-Box(2)=A. Result = 6A.
    
- $w_4 = w_2 \oplus RCON2 \oplus 6A = DD \oplus 30 \oplus 6A$.
    
    - $DD = 1101 1101$
        
    - $30 = 0011 0000$
        
    - $6A = 0110 1010$
        
    - XOR = $1000 0111 = 87$.
        
- $w_5 = w_4 \oplus w_3 = 87 \oplus 28$.
    
    - $87 = 1000 0111$
        
    - $28 = 0010 1000$
        
    - XOR = $1010 1111 = AF$.
        
- **$K_2 = 87AF$**
    

2. Demonstrate Flow Diagram (S-AES)

The conversion flow is:

1. **Add Round Key ($K_0$)**
    
2. **Round 1:**
    
    - Nibble Substitution (S-Box)
        
    - Shift Row
        
    - Mix Columns
        
    - Add Round Key ($K_1$)
        
3. **Round 2:**
    
    - Nibble Substitution (S-Box)
        
    - Shift Row
        
    - Add Round Key ($K_2$)
        
4. **Result = Ciphertext**
    

5. Output after applying $K_0$ on Plaintext

Operation: $P \oplus K_0$

$P = D728$

$K_0 = 4AF5$

- $D (1101) \oplus 4 (0100) = 9 (1001)$
    
- $7 (0111) \oplus A (1010) = D (1101)$
    
- $2 (0010) \oplus F (1111) = D (1101)$
    
- $8 (1000) \oplus 5 (0101) = D (1101)$
    

**Output = 9DDD**
