# 1.3 Classical Cryptography and its Limitations

Classical ciphers utilized private-key encryption and generally fall into two categories: **substitution** and **transposition**.

## Substitution Ciphers

These replace letters of plaintext with other letters, numbers, or symbols.

• **Caesar Cipher:** The earliest known substitution cipher. It replaces each letter by the letter 3 places down (a shift k=3). Mathematically, encryption is C=(p+k)mod26.

    ◦ **Limitation:** It is extremely weak, having only 26 possible keys (shifts), making it easy to break by brute force search.

• **Monoalphabetic Ciphers:** These shuffle the alphabet arbitrarily, so each plaintext letter maps to a different random ciphertext letter. The key is 26 letters long.

    ◦ **Limitation:** Despite having 26! (approx. 4×1026) possible keys, they are insecure due to **language characteristics and redundancy**. They do not change the **relative letter frequencies** of the original text, allowing cryptanalysis using frequency analysis (discovered by Arabian scientists in the 9th century),.

• **Polyalphabetic Ciphers:** Improve security by using multiple cipher alphabets, making cryptanalysis harder and flattening the frequency distribution,.

    ◦ **Vigenère Cipher:** The simplest polyalphabetic cipher, effectively a sequence of multiple Caesar ciphers. A keyword (K=k1​k2​...kd​) determines which Caesar shift is used for each letter, repeating the key after d letters,.

## Transposition Ciphers

These **hide the message by rearranging the letter order** (permutation) without changing the actual letters used.

• **Limitation:** They can be recognized because the ciphertext retains the same frequency distribution as the original plaintext.

• **Rail Fence Technique:** A simple transposition method where the plaintext is written out diagonally.

• **Row Transposition Ciphers:** Letters are written out in rows over a specified number of columns, and then the columns are reordered according to a key before the ciphertext is read off,.

## Limitations and Product Ciphers

Ciphers relying solely on substitutions or transpositions are ultimately insecure because of inherent language characteristics. Modern security requires **Product Ciphers**, which combine operations. A substitution followed by a transposition creates a much harder cipher, serving as the bridge from classical to modern ciphers.
