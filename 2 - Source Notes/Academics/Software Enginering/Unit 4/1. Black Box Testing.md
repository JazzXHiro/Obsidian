# 1. Black Box Testing

## Black-Box Testing

- **Definition**  
    Testing functionality without any knowledge of the internal code or structure; tests are based solely on requirements and specifications stated by the customer .
    

## Types of Black-Box Testing

### 1. Regression Testing

- **Purpose**: Conducted after code updates to verify no new bugs were introduced.  
- **Rationale**: New code may conflict with existing logic, causing defects.  
- **Process**: QA teams maintain regression test cases for critical features to:  
  - Re-execute after changes  
  - Save time  
  - Maximize test efficiency

#### When to Perform Regression Testing

Regression testing is performed in these scenarios:  

- **New functionality** is added to the application  
- **Requirement changes** occur  
- A **defect is fixed**  
- A **functional/performance issue** is resolved  
- There is an **environment change**

**Example:** A software team develops an e-commerce website. The testing team creates 1000 test cases to check every aspect of the application. After adding new features or updates, the QA team does regression testing by creating 100 new test cases and re-executing the previous 1000. This ensures the website works as intended and maintains software quality.

### 2. Equivalence Partitioning

- **Definition**: Software testing technique dividing input data into valid/invalid partitions where all partitions must exhibit identical behavior.  
- **Key Principles**:  
  - If one partition's condition is **true**, all equivalent partitions must be **true**.  
  - If one partition's condition is **false**, all equivalent partitions must be **false**.  
  - Test cases must cover **each partition at least once**.  
- **Source**: Partitions are derived from software **requirements/specifications**.  
- **Advantage**: Reduces testing time by converting infinite test cases to a **finite set**.  
- **Applicability**: Used at **all levels** of testing.

**Example:** Assume that there is a function in a software application that accepts a specific number of digits—no more and no less. For example, an OTP field that only allows exactly six digits. If the user enters fewer or more than six digits, the application will reject the input and redirect the user to an error page.
