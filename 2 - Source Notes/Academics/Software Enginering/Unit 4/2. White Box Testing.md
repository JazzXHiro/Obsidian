# White Box Testing

## White Box Testing

- **Alternative Names**:  
  Glass box testing, Clear box testing, Structural testing  
- **Primary Goal**:  
  Focus on input/output flow and enhance software security  
- **Internal Perspective**:  
  Tests internal structures (code, design, data structures) rather than just functionality  
- **Key Characteristics**:  
  - Analyzes inner workings of software  
  - Unlike black box testing which focuses on external behavior

# Control Structure Testing

- **Purpose**: Increases test coverage by examining control structures in the program.  
- **Types**:  
  1. **Condition Testing**  
  2. **Data Flow Testing**  
  3. **Loop Testing**

## 1. Condition Testing

- **Definition**: Test design method ensuring logical conditions and decision statements are error-free.  
- **Tested Conditions**:  
  1. **Relational Expressions**:  
     `E1 op E2` (E1, E2 = arithmetic expressions; `op` = operator)  
  2. **Simple Conditions**:  
     `~E1` (E1 = arithmetic expression; `~` = NOT operator)  
  3. **Compound Conditions**:  
     `(E1 & E2) | (E2 & E3)` (Boolean operators `&`, `|` with parentheses)  
  4. **Boolean Expressions**:  
     `A | B` (Operands with `AND`, `OR`, `NOT` operators)

## 2. Data Flow Testing

- **Purpose**: Tracks data movement through a program to detect anomalies.  
- **Identifies Issues**:  
  - Uninitialized variables  
  - Unused variables  
  - Improper data modifications 

## 3. Loop Testing

- **Type**: White box testing technique  
- **Focus**: Validates the correctness of loop constructs

# Decision-to-Decision Path (DD-Path)

- **Definition**: An execution path between two decisions in a program flow graph (e.g., flowchart).  
- **Alternative Name**: Segments  
- **Example Paths**:  
  - `1-2-5-6`  
  - `3-4`
    ![[Pasted image 20250515040711.png||400||150]]
- ### DD-Path (Decision-to-Decision Path) Definition
  A DD-path is a set of nodes in a program graph where one of these conditions holds:

	1. Single node with in-degree = 0 (initial node)  
	2. Single node with out-degree = 0 (terminal node)  
	3. Single node with in-degree ≥ 2 or out-degree ≥ 2 (decision/merge points)  
	4. Single node with in-degree = 1 and out-degree = 1  
	5. Maximal chain of length ≥ 1

# Basis Path Testing

- **Objective**: Path Testing aims to uncover errors, defects, and unexpected outcomes that might occur when the application takes different paths.
- **Approach**: Systematically explores all possible routes to identify:  
  - Vulnerabilities  
  - Logic errors  
  - Discrepancies  
- **Type**: White-box testing technique based on program control structure.  
- **Method**:  
  1. Prepare a **control flow graph** from the program structure.  
  2. Execute all possible paths in the graph during testing.

## Basis Path Test Case Design Steps

1. **Construct** the Control Flow Graph  
2. **Compute** the Cyclomatic Complexity  
3. **Identify** Independent Paths  
4. **Design** Test Cases from Independent Paths

## Cyclomatic Complexity

- **Definition**: A measure of a program's logical complexity, denoted as **V(G)**.  
- **Calculation Methods**:  
  1. **Edges and Nodes** formula  
  2. **Decision Nodes** formula  
  3. **Number of Regions** formula

### 1. Cyclomatic Complexity Calculation (Edges and Nodes Formula)

![[Pasted image 20250515041809.png||400]]

**\[ V(G) = e - n + 2P \]**

**Where**:  
- \( e \) = number of edges  
- \( n \) = number of vertices  
- \( P \) = number of connected components  

**Example**:  
- \( e = 4 \), \( n = 4 \), \( P = 1 \)  
- ( V(G) = 4 - 4 + 2 $\times$ 1 = 2)

### 2. Cyclomatic Complexity Calculation (Decision Nodes Formula)

![[Pasted image 20250515041938.png||400]]

**\[ V(G) = D + 1 \]**

**Where**:  
- \( D \) = number of decision nodes  

**Example**:  
- \( D = 1 \)  
- \( V(G) = 1 + 1 = 2 \)  

### 3. Cyclomatic Complexity Calculation (Regions Formula)

![[Pasted image 20250515042546.png||400]]

$V(G) = \text{Number of regions in the graph}$

**Example**:  
- **Region 1**: 1  
- **Region 2**: 1  
- **Total V(G): 1 + 1 = 2**
