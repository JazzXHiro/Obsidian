# Code Snippet 1 - JS

## 🧠 The Code

```js
if (navToggle) {
  navToggle.addEventListener('click', () => {
    navMenu.classList.add('show-menu');
  });
}
```

---

## 1️⃣ `if (navToggle) { ... }` — Safety Check

### What this does

This checks whether `navToggle` **actually exists**.

Why needed?

```js
const navToggle = document.getElementById('nav-toggle');
```

If there is **no element** with that ID:

```js
navToggle === null;
```

Calling `.addEventListener()` on `null` would crash your script.

So this line means:

> “Only run the code if the element exists.”

✔ Prevents runtime errors  
✔ Makes code reusable across pages

---

## 2️⃣ `navToggle.addEventListener('click', ...)` — Event Listener

### What this does

Attaches a **click event listener** to the element.

Meaning:

> “When the user clicks this element, run the function.”

This is how JavaScript **reacts to user actions**.

---

## 3️⃣ `'click'` — The Event Type

Common events:

- `click`
    
- `mouseover`
    
- `keydown`
    
- `scroll`
    

Here:

- The function runs **when the element is clicked**

---

## 4️⃣ `() => { ... }` — Arrow Function (Callback)

This is the **callback function**.

It is:

- Not executed immediately
    
- Stored and called later by the browser
    
- Triggered only when the event happens
    

Think of it as:

> “Run this code later, when clicked.”

---

## 5️⃣ `navMenu.classList.add('show-menu')` — DOM Manipulation

### What this does

Adds a CSS class to the menu element.

```js
navMenu.classList.add('show-menu');
```

Result:

- The menu gains the `show-menu` class
    
- CSS tied to `.show-menu` activates
    
- Menu becomes visible (slides down, fades in, etc.)
    

Example CSS:

```css
.show-menu {
  top: 0;
}
```

### Does show-menu's top replace the top in nav__menu?

Yes—when `.show-menu` is applied, its `top` value overrides the `top` set on `.nav__menu` (because they have the same specificity and `.show-menu` appears later in your CSS).

How it works in your case:

- In your mobile media query, `.nav__menu` starts hidden off-screen:

```css
@media screen and (max-width: 1150px){
  .nav__menu{
    top: -120%;
    transition: top .4s;
  }
}
```

- When JS runs `navMenu.classList.add('show-menu')`, the element now matches both selectors:
    - `.nav__menu` (so it still has `position: fixed`, `transition`, etc.)
    - `.show-menu` (so it gets `top: 0`)

```css
.show-menu{
  top: 0;
}
```

Result:

- `top: 0` “replaces” (overrides) `top: -120%`
- because `transition: top .4s` is still active from `.nav__menu`, it animates smoothly from `-120%` to `0`.

One important detail: this override only works if `.show-menu { ... }` is defined **after** the `.nav__menu { ... }` rule in the CSS (which yours is).

```
Does this truly replace the value or just creates a new variable inside the nav__menu inherited from show-menu and since that value is after the first one, it is over-ridden by the new value. i.e. 0.
```

It does **not** create a new “variable” inside `.nav__menu`, and it’s also **not inheritance**.

What’s really happening is the **CSS cascade** decides the element’s final (computed) `top` value based on which rules match.

#### When the menu is closed

The element matches:

- `.nav__menu { top: -120%; }` (inside your mobile `@media`)

So its computed `top` is `-120%`.

#### When you add `show-menu`

Now the same element matches **two rules** that both set `top`:

- `.nav__menu { top: -120%; }`
- `.show-menu { top: 0; }`

CSS must pick one value. It uses the cascade order:

1. `!important` (none here)
2. Specificity (both are one class selector → same specificity)
3. Source order (the rule that appears later in the CSS wins)

Since `.show-menu { top: 0; }` is written later, `top: 0` **wins** and becomes the element’s computed value.

#### When you remove `show-menu`

The `.show-menu` rule no longer matches, so CSS falls back to the remaining matching rule (`.nav__menu { top: -120%; }`).

#### Key wording

- It “replaces” the value **in the computed style**, not by changing the original rule.
- It’s **override via cascade**, not inheritance, and not a new variable.
