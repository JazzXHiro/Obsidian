# 🧠 CSS Parsing — Step by Step (How Browsers Really Work)

When a browser loads your webpage, it doesn’t “apply CSS magically”.  
It follows a **strict pipeline**.

---

## 🔁 High-Level Pipeline (Big Picture)

![Image](https://webperf.tips/static/d77eb220c5dd10181dc361c4ff0051da/906b5/BrowserRenderingPipeline17.png)

![Image](https://web.dev/static/articles/critical-rendering-path/render-tree-construction/image/dom-cssom-are-combined-8de5805b2061e.png)

```
HTML → DOM
CSS  → CSSOM
DOM + CSSOM → Render Tree
Render Tree → Layout
Layout → Paint
```

Now let’s zoom in **only on the CSS part**.

---

## 1️⃣ Browser Downloads the CSS

Example:

```html
<link rel="stylesheet" href="style.css">
```

The browser:

- Sees the `<link>`
    
- Sends a request for `style.css`
    
- Downloads it
    

⚠️ CSS is **render-blocking**  
→ Browser waits before painting the page.

---

## 2️⃣ CSS Is Tokenized (Broken into Pieces)

The browser reads CSS **character by character** and converts it into tokens.

Example CSS:

```css
.nav__link {
  color: red;
}
```

Tokens:

- `.nav__link` → selector token
    
- `{` → block start
    
- `color` → property
    
- `:` → separator
    
- `red` → value
    
- `;` → declaration end
    
- `}` → block end
    

This is **lexical analysis**.

---

## 3️⃣ CSS Is Parsed into Rules

Now tokens are grouped into **CSS rules**.

The browser builds an internal structure like:

```
Rule
 ├─ Selector: .nav__link
 └─ Declarations:
      └─ color: red
```

If CSS is invalid:

```css
color red;
```

❌ Browser ignores **only that declaration**, not the whole file.

---

## 4️⃣ Browser Builds the CSSOM (CSS Object Model)

All parsed rules are stored in a tree called the **CSSOM**.

The CSSOM is:

- A structured object
    
- Similar to the DOM
    
- Represents **all CSS rules**
    

Important:

> **CSSOM includes cascade, inheritance, and specificity info.**

---

## 5️⃣ Selector Matching (Very Important)

Now the browser asks:

> “Which rules apply to which elements?”

It does this by:

- Walking the **DOM**
    
- Matching selectors **right-to-left** (performance optimization)

Example:

```css
.nav__menu a {
  color: white;
}
```

Browser checks:

1. Find all `<a>`
    
2. Check if parent has `.nav__menu`

✔ Match → rule applies

---

## 6️⃣ Cascade Resolution (Conflict Solving)

If multiple rules match the same element/property:

```css
a { color: red; }
.nav__link { color: blue; }
```

Browser resolves conflicts using **cascade order**:

1. `!important`
    
2. Origin
    
3. Specificity
    
4. Source order

Result:

```css
color: blue;
```

This step produces the **final computed style**.

---

## 7️⃣ Inheritance Is Applied

Some properties inherit automatically:

- `color`
    
- `font-family`
    
- `font-size`

If an element doesn’t define them:  
→ browser inherits from parent.

Example:

```css
body { color: white; }
```

All children become white **unless overridden**.

---

## 8️⃣ Render Tree Is Built (DOM + CSSOM)

Browser combines:

- DOM nodes
    
- Final computed CSS styles

Into the **Render Tree**.

❌ Nodes like:

- `display: none`
    
- `<head>`

are **excluded**.

---

## 9️⃣ Layout (Position & Size Calculation)

Browser calculates:

- Width
    
- Height
    
- Position

Based on:

- Flexbox
    
- Grid
    
- Box model
    
- Viewport size

This step is called **reflow**.

---

## 🔟 Paint (Pixels on Screen)

Finally:

- Browser paints pixels
    
- Applies colors, borders, shadows
    
- GPU may assist

🎉 Page becomes visible.

---

## 🧠 What Happens When You Change a Class with JS?

```js
navMenu.classList.add("show-menu");
```

Browser:

1. Recalculates CSSOM matches
    
2. Resolves cascade again
    
3. Updates render tree
    
4. Runs layout (if needed)
    
5. Paints changes

If a `transition` exists → animation happens.

---

## ⚠️ Performance Insight (Interview Gold)

|Change|Cost|
|---|---|
|`color`, `opacity`|Paint only (cheap)|
|`top`, `width`|Layout + paint|
|`transform`|GPU-accelerated (best)|

This is why animations prefer:

```css
transform
opacity
```
