# form - HTML

## What is a `<form>` in HTML?

A `<form>` is used to **collect user input and send it to a server or handle it with JavaScript**.

Typical uses:

- Login / signup
    
- Contact forms
    
- Search bars
    
- Feedback forms

---

## Basic structure

```html
<form>
  <!-- form controls -->
</form>
```

A form itself does nothing visually. It becomes useful only when it contains **form controls**.

---

## Common form controls

Inside a form, you usually have:

```html
<input>
<textarea>
<select>
<button>
```

Example:

```html
<form>
  <input type="text" placeholder="Your name">
  <button type="submit">Submit</button>
</form>
```

---

## Key `<form>` attributes

### `action`

Specifies **where the form data is sent**.

```html
<form action="/submit">
```

- URL or endpoint
    
- If omitted, data is sent to the **current page**
    

---

### `method`

Specifies **how the data is sent**.

```html
<form method="get">
<form method="post">
```

- `GET`
    
    - Data goes in the URL
        
    - Used for searches
        
- `POST`
    
    - Data goes in the request body
        
    - Used for sensitive data

---

### `name`

Identifies the form (used in JS or backend).

```html
<form name="contactForm">
```

---

## How data is collected

Each input must have a **`name` attribute**.

```html
<input type="email" name="email">
```

When submitted, the browser sends:

```
email=user@example.com
```

Without `name`, the input is **ignored**.

---

## Submitting a form

### Default behavior

- Clicking a submit button
    
- Pressing Enter inside an input

```html
<button type="submit">Send</button>
```

The browser:

1. Validates inputs
    
2. Sends data to `action`
    
3. Reloads or redirects the page

---

## Preventing default submission (JavaScript)

Used in modern websites:

```html
<form id="contact">
  <input name="email">
  <button>Send</button>
</form>
```

```js
document.getElementById("contact").addEventListener("submit", e => {
  e.preventDefault();
  // handle form with JS
});
```

This allows:

- AJAX requests
    
- Client-side validation
    
- No page reload

---

## Built-in HTML validation

HTML forms provide free validation:

```html
<input type="email" required>
<input type="password" minlength="8">
```

The browser blocks submission if rules fail.

---

## Accessibility importance

- `<form>` provides semantic meaning
    
- Screen readers understand form boundaries
    
- `<label>` works properly only with form controls

Correct usage:

```html
<label for="email">Email</label>
<input id="email" name="email">
```

---

## `<form>` vs `<div>`

|Aspect|`<form>`|`<div>`|
|---|---|---|
|Semantic|Yes|No|
|Submittable|Yes|No|
|Validation|Built-in|No|
|Accessibility|Strong|Weak|

Never replace a form with a div.

---

## Common mistakes

- Forgetting `name` on inputs
    
- Using `<div>` instead of `<form>`
    
- Not preventing default submit when using JS
    
- Using `GET` for sensitive data

---

## Interview-ready definition

> “The `<form>` element groups input controls and enables user data submission, validation, and interaction with servers or JavaScript.”

---

## One-line rule

**Use `<form>` whenever user input needs to be collected or submitted.**
