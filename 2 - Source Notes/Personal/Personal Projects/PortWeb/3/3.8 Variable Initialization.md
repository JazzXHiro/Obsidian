# Variable Initialization

## 🧠 Short Answer

> **Assigning a value without a declaration (`var`, `let`, `const`) can implicitly create a variable — but only in non-strict mode, and it becomes global.**

This is **bad practice** and usually a bug.

---

## 🧪 Example: Assignment WITHOUT Declaration

```js
x = 10;
```

### What happens?

- If **not in strict mode**:
    
    - JS creates a **global variable** `x`
        
- If **in strict mode**:
    
    - ❌ `ReferenceError`

---

## 🔍 Non-Strict Mode (Default in old JS)

```js
function test() {
  y = 20;
}
test();

console.log(y); // ✅ 20
```

What happened?

- `y` was **never declared**
    
- JS silently created:
    

```js
window.y = 20;
```

⚠️ This is called **implicit global variable creation**.

---

## 🚨 Why This Is Dangerous

- Pollutes global scope
    
- Causes naming collisions
    
- Creates hard-to-debug bugs
    
- Breaks modular code
    
- Fails silently
    

That’s why modern JS **forbids this** in strict mode.

---

## 🔒 Strict Mode (Modern JavaScript)

```js
"use strict";

x = 10; // ❌ ReferenceError
```

Here:

- JS refuses to create variables implicitly
    
- You **must** declare variables explicitly
    

---

## 🆚 Declaration vs Initialization (Important Distinction)

|Action|Example|Result|
|---|---|---|
|Declaration|`let a;`|Variable exists|
|Initialization|`a = 5;`|Value assigned|
|Declaration + init|`let a = 5;`|Correct|
|Init without decl|`a = 5;`|❌ Implicit global (non-strict)|


---

## 🎯 Interview-Ready Answer

> “Assigning a value without declaring a variable does not properly declare it; in non-strict mode it creates an implicit global variable, and in strict mode it throws a ReferenceError.”
