# 3.9 Why var is avoided - JS

# Why `var` Is Avoided in JavaScript

`var` is **not wrong**, but it has **dangerous behaviors** that caused many bugs.  
Modern JavaScript prefers **`let` and `const`** because they fix these problems.

---

## 1️⃣ `var` Is **Function-Scoped**, Not Block-Scoped ❌

### With `var`

```js
if (true) {
  var x = 10;
}
console.log(x); // ✅ 10 (unexpected)
```

`x` leaks **outside the block**.

---

### With `let` / `const`

```js
if (true) {
  let y = 10;
}
console.log(y); // ❌ ReferenceError
```

✔ Block scope  
✔ Safer  
✔ Predictable

---

## 2️⃣ `var` Allows **Redeclaration** ❌

```js
var a = 5;
var a = 10; // ❌ No error
```

This can:

- Overwrite values silently
    
- Cause logic bugs
    

---

### `let` / `const` prevent this

```js
let a = 5;
let a = 10; // ❌ Error
```

✔ Bugs caught early

---

## 3️⃣ `var` Is Hoisted to `undefined` ❌

```js
console.log(b); // undefined
var b = 10;
```

This hides errors and creates confusion.

---

### `let` / `const` use TDZ (Good)

```js
console.log(c); // ❌ ReferenceError
let c = 10;
```

✔ Forces correct ordering  
✔ Cleaner logic

---

## 4️⃣ `var` Creates Implicit Globals (Very Dangerous) ❌

```js
function test() {
  var x = 5;
}
```

But accidentally:

```js
function test() {
  x = 5; // ❌ global variable created
}
```

This pollutes the global scope.

`let` / `const` + strict mode **prevent this entirely**.

---

## 5️⃣ `var` Breaks Loops & Closures ❌

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
```

Output:

```
3
3
3
```

Why?  
Because `var` is function-scoped.

---

### Correct with `let`

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
```

Output:

```
0
1
2
```

---

|Feature|`var`|`let`|`const`|
|---|---|---|---|
|Block scoped|❌|✅|✅|
|Redeclaration allowed|❌ bad|❌|❌|
|Hoisting safety|❌|✅|✅|
|TDZ protection|❌|✅|✅|
|Loop safety|❌|✅|✅|
|Best practice|❌|✅|⭐⭐⭐|

---

## 🧠 Modern JavaScript Rule (Very Important)

> **Use `const` by default**  
> **Use `let` if reassignment is needed**  
> **Never use `var`**

This is industry standard.

---

## 🎯 Interview-Ready Answer

> “`var` is avoided because it is function-scoped, allows redeclaration, causes hoisting-related bugs, and can leak variables into the global scope. `let` and `const` provide safer block scoping and predictable behavior.”
